# 发布到 GitHub

此版本已在本地整理；以下是发布者自行执行的步骤，不表示仓库已经创建或上传。

1. 阅读 README、许可证、第三方声明与验证记录，确认希望以 MIT 提供源码。
2. 在干净目录解压源码包。不要直接上传已经运行过的整个工作目录。
3. 执行源码检查，人工复核公开文件、配置模板、截图及第三方内容。
4. 在该目录初始化新的 Git 历史，提交前查看待提交文件；不继承包含私人资料的历史。
5. 在 GitHub 创建仓库，按自己选择的仓库名和公开范围配置远端。上传前再次核对是否确实要公开。
6. 发布首版并说明验证范围、已知限制和贡献方式。仓库名、所有者、维护者联系方式由发布者填写，本项目不预填个人信息。

源码检查和本地打包：

```sh
python tools/check_release.py
python tools/package_release.py ../stock-research-source.zip
```

打包器只收录显式允许的源码、模板、虚构示例、文档与截图，不收录 `.git`、有效配置、密钥、数据库、运行日志、真实网页数据或归档。输出包含逐文件 SHA-256 清单，ZIP 条目使用统一的非个人元数据。

如果已经在工作副本填写了自己的密钥，应该从源码白名单重新生成包；不把“先上传再删除”当作脱敏方法。GitHub 源码公开与在线托管应用是两件事，首版无需将本机设置服务暴露到公网。
